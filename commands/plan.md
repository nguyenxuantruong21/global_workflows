Task: $ARGUMENTS

Do not implement.

1. Read the relevant code and project docs. Research externally only if the task needs it.
2. Ask only the questions that change the plan.
3. Save the plan to `plans/YYMMDD-short-task-name.md`:

```markdown
# {Title}
Status: pending

## Goal
{What is being built and why}

## Decisions
{Key choices and reasons}

## Phases
### Phase 1: {name}
- [ ] {task, naming the files involved}

## Done when
{How to verify the result, including the commands to run}

## Risks
{Only real risks; omit if none}
```

Use only as many phases as the task needs. A small task can have one.

4. Show the plan path and summary, and list open questions.
